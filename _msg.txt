fix(probe): stop trusting conversation reads as "this turn", and make the button visible

The user reported the panel showing gpt-5.5-2026-04-23 for a conversation
that was actually running opus-5. Two separate defects.

1) The false model name -- pitfall 7 came back.

   The fast channel's source allowlist contained /api/chat/, which let
   through every endpoint under it -- including ones that READ the
   conversation rather than being the current turn:

     /api/chat/<id>/preview            (returns the chat title)
     /api/chat/<id>/workspace/latest
     /api/chat/<id>/run-status

   Since this tool can rename a conversation to the model name, the title
   IS a model name. So merely opening a conversation reported the previous
   model as the current one. The rename feature has been writing those
   names all along (65x gpt-5.6-sol, 57x claude-opus-5, 25x
   gpt-5.5-2026-04-23 ...), so the pollution source was always there.

   Now only the actual stream is trusted: /api/chat/<id>/stream|message(s)
   |events is allowed, and anything else under /api/chat/ is rejected
   because it is reading history. Other noise endpoints (workspace,
   review-feedback, connectors, pulse, rum, logs) are excluded too.

   Reproduced first, then fixed: with a fake arena.ai whose /preview
   returns a gpt-5.5 title, the old code reported gpt-5.5 every time and
   the new code correctly reports nothing.

2) A wrong value, once written, stayed on the panel forever.

   state.fastModel is only replaced when a new turn arrives, so an
   unconfirmed wrong name persisted indefinitely. "Check model" now means
   "judge this again": unconfirmed fast results and tiers are cleared and
   re-derived, while a trace-confirmed model (the authoritative result) is
   left alone. Verified by injecting a stale wrong value and confirming it
   is gone after the check.

Also made the button findable. It was a .more text link sitting next to
"details" in 10.5px muted grey -- the user could not find it, which is a
fair complaint about a rescue button. It is now a real button sharing a
row with "details".

Full offline suite re-run after the change (5 scenarios, all passing):
the true current-turn stream still drives the fast channel, so the
narrowing did not break detection -- the project has been burned before by
a fast channel tightened into never firing.
